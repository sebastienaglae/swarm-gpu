# Phase 04 — GPU culling and compaction

## Objective

Keep visibility decisions entirely on the GPU, compact visible instance IDs, generate indirect arguments, and render without returning visible counts to JavaScript each frame.

## Entry criteria

- Phase 03 simulation is correct and stable.
- Camera/frustum conventions from Phase 02 are unit-tested.

## Pass sequence

```text
reset counters/indirect instance counts
  -> simulate
  -> cull and atomic-append visible IDs
  -> finalize indirect arguments
  -> drawIndexedIndirect
```

The simplest correct v1 compaction uses one atomic counter per LOD/output list. More elaborate prefix scans are Phase 09 unless contention is demonstrated as a primary bottleneck.

## Buffer contracts

- `visibleIds`: capacity for every active instance, partitioned or separately allocated by LOD.
- `visibilityCounters`: atomic `u32` counts, reset each frame by `clearBuffer` or a tiny compute pass.
- `indirectArgs`: five `u32` fields per indexed draw (`indexCount`, `instanceCount`, `firstIndex`, `baseVertex`, `firstInstance`) with required usage flags and alignment.
- Instance count written by GPU; mesh constants initialized once or regenerated by a finalize pass.

Every atomic append checks destination capacity. Correctness must not depend on a culling result being smaller than the active population.

## Implementation work

### Frustum data

- [x] Extract six normalized planes from the exact view-projection convention.
- [x] Upload planes in a stable aligned global block.
- [x] Define sphere radius from mesh bound multiplied by per-instance scale and a documented safety margin.
- [x] Unit-test points/spheres inside, outside each plane, intersecting, behind camera, and at far limit.

### Counter reset and culling

- [x] Reset counters and indirect instance fields before append dispatch.
- [x] Cull active instances with guarded invocation IDs.
- [x] Atomically reserve output slots and write source instance IDs.
- [x] Prevent writes when the reserved slot is outside capacity, while tracking overflow in diagnostic builds.
- [x] Keep culling conservative to prevent visible popping at the frustum edge.

### Indirect generation

- [x] Finalize one valid indirect record from GPU counters without CPU intervention.
- [x] Use `drawIndexedIndirect` with offsets validated against WebGPU alignment requirements.
- [x] Modify vertex fetching so `instance_index` selects a compact visible ID, then fetches simulation and appearance state.
- [x] Preserve a development direct-draw/reference path behind a build/debug control.
- [x] Assert resource usages include STORAGE, INDIRECT, COPY_DST/COPY_SRC only where actually needed.

### Diagnostics without frame readback

- [x] Live visible count is either labeled delayed/periodic and read outside critical measurement windows, or omitted when it would violate the contract.
- [x] Benchmark mode may copy counters after its measured window and associate results with the report.
- [x] Add a debug capture action that pauses, copies visible IDs/counters, validates them, and resumes only on user request.
- [x] Ensure default metrics do not call `mapAsync` per frame.

## Correctness tests

- CPU frustum reference versus shader result on seeded small populations.
- All-visible, all-hidden, exactly-capacity, zero-active, and partially filled final workgroup cases.
- Counter reset across consecutive frames with radically different camera views.
- Indirect arguments byte layout and offsets.
- Visible ID uniqueness/range in paused debug captures.
- Direct-reference and indirect-render screenshots for deterministic fixtures.

## Performance experiments

- Compare no-culling direct draw versus atomic compaction plus indirect draw at 10%, 50%, and 100% visibility.
- Measure culling/compaction time independently with timestamp queries where available.
- Determine the visibility break-even point and document that culling can cost more than it saves in all-visible scenes.
- Test contention at 1m all-visible; only promote a prefix-scan design if evidence justifies its complexity.

## Exit criteria

- The normal frame loop performs simulation, culling, compaction, indirect generation, and indirect drawing without GPU readback.
- Culling matches the CPU reference for deterministic fixtures and remains conservatively correct at frustum edges.
- Counter overflow cannot corrupt memory.
- Camera changes produce correct visibility on the following encoded frame without stale counters.
- Performance comparison and break-even analysis are recorded honestly.

## Risks and mitigations

| Risk                                                     | Mitigation                                                                                 |
| -------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| Atomic append bottlenecks when all instances are visible | Measure first; consider workgroup compaction/prefix scan only as evidence-driven follow-up |
| Plane convention silently culls everything               | Share tested extraction fixtures and retain direct reference mode                          |
| Visible-count overlay introduces hidden synchronization  | Disable periodic readback during measurements and disclose its cadence                     |
| Capacity partition wastes memory                         | Start simple, document cost, optimize only after profiling                                 |
